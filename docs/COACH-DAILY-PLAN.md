# 教練起始計畫與每日 08:00 對話提醒

## 使用者會看到什麼

- 首次開啟教練，立即收到自己的每週訓練與每日飲食起始安排。頂端「我的計畫」卡可隨時展開。
- 依目前個人檔案的年齡、身高、體重、目標體重、增肌／維持／減脂目標、活動量、營養目標與備註建立。活動量較低或高齡先安排每週兩次，其餘預設三次全身訓練，並註明尚未取得訓練經驗與器材等資訊。
- 徒手與素食備註會選用相應範例；未指定器材時明示以啞鈴／滑輪安排。特殊健康限制或未成年先請使用者確認條件，避免直接套一般成人課表。自由文字不是完整健康評估，也不保證辨識所有限制。
- 食物只是搭配範例；每餐數字是分配的「目標」，不宣稱這份餐點含有精確營養值。三餐及點心的熱量、蛋白質目標加總等於個人檔案中的每日目標。
- 規則式起始計畫不需 Gemini，不會因模型排隊而讓預設計畫一直 loading。一般 AI 問答也會帶入這份計畫；使用者可繼續告訴教練器材、經驗與限制，請教練提出調整建議。只有個人檔案變更會自動更新持久化起始計畫；純聊天提出的替代方案不會冒稱已改寫固定課表。

## 時間、重複防護與離線

- 時區固定為 `Asia/Taipei`，不依賴 Windows／WSL 的系統時區。
- 伺服器每分鐘對已啟用的正式帳號檢查；每日 08:00 起，寫入一則私人的當日飲食與運動訊息。對話頁每 30 秒同步；從背景回到頁面也立即同步。
- 這是對話訊息，無需 VAPID 或瀏覽器推播訂閱。原本 12／15／18／21 點的熱量推播仍由原本設定管理。
- 服務須運作才能準時產生提醒。筆電睡眠、關機或服務中斷時，恢復後僅補「當天」；不補刷過去多天的提醒。
- 試用訪客不跑背景排程；進入自己的教練頁時仍會建立起始計畫與當天到期訊息，資料隨訪客帳號既有生命週期刪除。
- 當天已記運動不要求重做；昨天有重量訓練時優先恢復。恢復日有輕鬆活動建議。
- 所有建議都不寫入飲食、訓練紀錄，不發完成獎勵。

## 如何製作

1. `db.js` 透過 `CREATE TABLE IF NOT EXISTS` 增加兩個表，既有資料保留：`coach_plans` 以個人資料雜湊快取計畫；`coach_deliveries` 以 `(kind, delivery_key)` 作唯一鍵。
2. `coach-plan.js` 的 `buildCoachPlan` 是純函式，依個人資料建立安排；`taipeiClock` 透過 `Intl.DateTimeFormat` 明確換算台灣日期與小時。
3. `getCoachPlan` 對影響計畫的資料作 SHA-256；檔案變更才建立新版本，不因單純時間戳更新而重複發送。
4. `deliver` 使用 `BEGIN IMMEDIATE`，把聊天訊息與發送收據放在同一交易中。收據寫入失敗時連訊息一起回滾。重啟、多分頁、重複查詢都不會重送同一天的提醒。
5. `scheduler.js` 啟動獨立的教練檢查，即使 VAPID 未設定仍照常執行；`GET /api/chat/history` 與 `/api/chat/plan` 也檢查當日到期訊息，避免重開頁面漏掉。
6. `ChatView.vue` 顯示計畫卡並同步訊息；發送中與切換頁面時有檢查，不用背景刷新蓋掉使用者正在送出的訊息。
7. 清空聊天只刪聊天，不清發送收據，因此清空後當天不會立刻補回；計畫卡仍可查看，隔天會新增新的每日提醒。

## 驗證

`tests/coach-plan.test.js` 使用臨時資料庫，測試台灣 07:59／08:00 與跨日、同日只送一次、清空後不重送、晚啟動只補當日、營養分配總和、個人資料變更、素食／徒手、健康限制、近期訓練調整、帳號隔離與交易失敗回滾。沒有更動正式使用者紀錄。

訓練頻率的方向參考 [CDC 成人活動原則](https://www.cdc.gov/physical-activity-basics/guidelines/adults.html)；餐點組合參考 [加拿大健康餐盤](https://www.canada.ca/en/health-canada/services/food-guide/eating-support/cooking/make-healthy-meals-plate.html)。具體起始組數與餐次分配是本專案的規則，並非引用來源的逐字處方。
