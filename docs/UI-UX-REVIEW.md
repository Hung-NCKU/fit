# 健身養寵 UI／UX 審查與調整

日期：2026-10-26。

## 審查依據

使用實際部署版前端與隔離測試資料，檢查寵物、教練、今日、訓練、飲食，以及部署版已有的煮飯頁。正式使用者資料沒有作為測試寫入目標。

| 原本的問題 | 本次調整 | 使用者得到的改善 |
|---|---|---|
| 分頁藏在左下角「功能」，需先叫出且會自動收起 | 底部分頁常駐，移除把手與自動收合計時器 | 任一主要頁面直接點一次即可切換 |
| 功能列展開時改變內容位置 | 上標頭、內容捲動區、底列使用固定的 flex 配置 | 操作中不再因計時器收合而跳版，底列不覆蓋內容 |
| 標頭同時堆帳號、通知、安裝與登出 | 右上角帳號選單集中次要操作 | 標頭更短，通知保留文字名稱，登出與刪除放在選單下方 |
| 試用訪客需要建立帳號 | 保留試用者標頭上的直接建立帳號入口 | 不必先找設定選單 |
| 切頁可能帶入上一頁捲動距離 | 依完整路徑保存各頁內容捲動位置，切換帳號清除 | 回到原頁繼續看，首次進入別頁從頂部開始 |
| 米黃背景、按鈕與卡片彼此接近 | 奶油灰底、米白卡片、鼠尾草綠操作狀態 | 提高資訊層級，降低邊框與陰影的干擾 |
| 底部 Emoji 外觀不一致 | 本地 SVG 線條圖示，保留文字與選取色塊 | 所有平台的主要導覽外觀一致 |
| 寵物氣泡與下方說明重複 | 氣泡提醒不再於文字區重複顯示，操作說明可展開 | 小屋和數值更容易找到 |
| 只養一隻也出現選寵物按鈕 | 僅多寵物時顯示角色選擇列 | 減少無意義的控制項 |
| 心情與飽足度長條佔兩整排 | 並排顯示數字與細進度條 | 一眼比較狀態 |
| 全域按鈕樣式可能污染可互動圖片 | 寵物、裝飾和照片按鈕明確保留透明背景 | 避免點選時出現色塊，不更動房間尺寸或座標 |

## 行為與無障礙

- 主要導覽保留文字，使用 Vue Router 原生目前頁面狀態；導覽觸控目標至少 44×44。
- 帳號選單使用具名稱的按鈕、aria-expanded 與可標示區域；點外部或 Escape 關閉，Escape 將焦點交回觸發按鈕。通知與建立帳號原有面板操作保留。
- 使用者切換列有群組名稱與 aria-pressed 狀態。
- 鍵盤狀態沿用既有視窗偵測；收起標頭與導覽，教練輸入框保留，輸入文字不因收合遺失。
- 尊重減少動態效果偏好，並保留原有焦點外框。
- 保留商城釘選場景、房間布置手勢、單品排序、陪玩與獎勵邏輯。

## 驗證

瀏覽器以隔離 SQLite 資料啟動實際 API 和正式建置檔；測試沒有動正式資料庫。

- 原始碼版 320、390、820、1440 寬度 × 五個主要頁面：20 組配置。
- 部署版相同寬度 × 六個頁面（含煮飯）：24 組配置。
- 檢查各頁無水平溢出、內容與底列不重疊、導覽目標尺寸；等待超過原自動收合時間後仍顯示。
- 檢查帳號選單、通知面板、外部點擊與 Escape、切頁捲動位置恢復、飲食新增入口與鍵盤下輸入框。
- 模擬 iOS 安全區 47px／34px，底列仍貼齊 App 視窗底部；檢查行動版與桌面截圖。
- 單元測試與前端正式建置另行執行。

限制：iOS 測試為瀏覽器模擬，未以實體 iPhone 確認系統鍵盤及 PWA 系統保留區。不能據此保證所有 iOS 版本的系統區域都相同。此次未修改獎勵、營養計算或資料寫入規則。

### 動作清單回歸修正

共用控制項的 40px 最小高度曾覆蓋動作列原本的高度，長清單作為 flex 容器又會壓縮子項，造成中英文和器材資訊重疊。動作列改成 flex 不壓縮、至少 88px 並依內容自動增高，標題與副標分行顯示。另檢查 320／390／820／1440 寬度的所有動作列文字矩形都在項目內，彼此不重疊。寵物導覽圖示中央肉球改成實心以改善小尺寸辨識。

## 訓練紀錄按日期查看（2026-10-26）

訓練頁與飲食頁一樣提供日期選擇與前後日期導覽。左右箭頭跳到前後有紀錄的日子，亦可直接選空白日期或回到今天；畫面每次只顯示一天的肌力與有氧紀錄，並保留當日熱量、時間與各組明細。紀錄放在動作探索上方，新建訓練預設帶入所選日期（既有編輯／送出中內容不覆寫），儲存後切到實際儲存日期並捲回紀錄。

後端 `/api/workouts/page?date=YYYY-MM-DD&user=...` 同時回傳日期索引與指定一天紀錄；索引不受舊有300筆上限限制，空白日期不會被偷偷切回其他日期。快取以帳號與日期分開，寫入沿用既有失效機制，新增、移動日期和刪除後重讀最新資料；切換使用者會重設日期與清掉上一位的紀錄，跨帳號仍唯讀。

驗證：隔離 SQLite 測試305筆單日紀錄、完整日期索引、空白日、修改／刪除後索引、帳號隔離及無效日期；瀏覽器驗證前後切換、新增預設日期、儲存與刪除更新、另一帳號唯讀和320／390／820／1440寬度。

## 上次訓練與最高重量（2026-10-27）

選擇肌力動作時，讀取登入者相同名稱、相同分類、截至所選日期的最近一筆紀錄，逐組帶入重量、次數或秒數。完成勾選與 RPE 不沿用；畫面標示來源日期及原本數值，編輯本次欄位不會改變來源說明。恢復尚未儲存草稿時不重新覆寫。自訂動作填好名稱後，可按「帶入上次紀錄／查看最高重量」；已有填寫重量或完成組數會先確認取代。

最高重量 PR 是歷史每一組中實際記錄的最大 kg，附次數／秒數、日期與組別；不將累積訓練量或估算1RM當成最高重量。相同重量以次數較高、日期較新者顯示。支援舊版整體組數紀錄，徒手0kg不產生負重PR。PR由原始紀錄推算，新建、修正或刪除後，下次選擇動作就會反映最新結果，不另建可能失去同步的PR表。

`GET /api/workouts/history?exercise=...&category=...&before=YYYY-MM-DD` 回傳 `{workout, personalBest}`；此端點僅讀登入者自己的紀錄。日期界線避免補登時讀到未來的訓練。查詢失敗時可手動填寫；快速切換動作不套用較慢回來的舊結果。

驗證：測試上次與PR不同、不同組重量、同日排序、日期界線、修改／刪除重新計算、舊版紀錄、帳號隔離、0kg與無效查詢。瀏覽器確認逐組帶入、不自動完成、來源文字不隨本次編輯變動、無歷史預設、快速切換與斷線回退。
