# 頁面快取與 iOS 底部導覽

## 切頁先顯示，再更新

`web/src/page-cache.js` 只在目前 App 的記憶體保存頁面快照，不寫入 localStorage、sessionStorage、IndexedDB 或 service worker。寵物、今日、訓練、飲食與教練頁切回時先顯示上次資料，同時向 API 讀取最新內容；背景成功後取代快照，失敗保留舊畫面並顯示頁面原有錯誤。首次開啟或清除後仍需網路載入。

快取鍵包含頁面、登入帳號、正在查看的使用者與日期等查詢條件。最多保留 48 組快照；資料以獨立副本交給畫面，表單修改不會污染快取。同一頁同時讀取共用在途請求。

新增／修改／刪除成功時，`api.js` 依資源作廢相關頁面快照，立即在背景重新整理曾載入的相關頁面。飲食、訓練、體態會更新小屋／今日／教練及對應清單；個人目標會更新小屋、今日與教練；寵物動作更新小屋。作廢中的舊資料不再作為可顯示的快照，避免剛刪除的項目又出現。畫面原本儲存後的讀取可接續同一個背景請求。

每次異動增加版本號，舊請求即使較晚回來也不會覆蓋新快照。切換登入帳號、登出、授權失效，以及使用者頁籤切換時清空快取；清空後仍在途的舊帳號結果不能重新填回。HTTP API 仍維持 `no-store`，沒有放寬個人資料的共享快取。

今日頁背景更新不覆蓋已輸入的體態草稿；教練背景讀取不覆蓋送出訊息後的新對話狀態。快取只保存伺服器資料，不代替既有訓練草稿或送出收據。

## iPhone 首次啟動底部位置

原本整個 App 只依賴 CSS `100dvh`。本次改用 `app-height.js` 同步實際 `window.innerHeight`，首次掛載後再於動畫幀與 150／450／900ms 校正，涵蓋主畫面啟動過程的視窗變化。返回 App、pageshow、旋轉、resize、鍵盤開關也會更新。沒有用固定像素把導覽列往下推，原本的底部安全區仍保留。

鍵盤縮小可見區時使用 VisualViewport 高度；關閉輸入後恢復正常視窗高度。頁面縮放時不跟著修改容器高度。body 不另作外層捲動，保留 main 內容區捲動、場景拖移與原本的比例限制。

參考：[MDN innerHeight](https://developer.mozilla.org/en-US/docs/Web/API/Window/innerHeight)、[VisualViewport](https://developer.mozilla.org/en-US/docs/Web/API/VisualViewport)。這是在程式與模擬手機中修正高度同步；iOS 實機首次啟動仍需要使用者確認。

## 驗證

自動測試涵蓋快照立即顯示、背景更新、異動作廢、在途請求競態、清除後舊結果隔離及跨使用者鍵；高度測試涵蓋首次、恢復、旋轉、鍵盤及縮放。瀏覽器驗證刻意擋住訓練 API 時仍能先顯示快取，放行後更新內容，並檢查模擬安全區、首次高度校正及橫直向切換的導覽列底緣。
